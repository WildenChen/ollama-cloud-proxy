# Proxy 專屬金鑰升級與安全切換

本指南適用於從 1.5.1 或更早版本升級至 1.6.0，以及將 `CLIENT_API_KEYS` 環境變數金鑰逐步改成管理台金鑰的使用者。

## 升級前

請先備份：

- `.env`
- `data/`

不要更換或遺失 `KEY_ENCRYPTION_SECRET`。既有資料庫中的上游金鑰與 Proxy 專屬金鑰需要它才能解密。

## 升級不會自動改變什麼

1. 不會自動更換、停用或刪除任何既有 Client API Key。
2. 不會修改 `.env` 或把 `CLIENT_API_KEYS` 自動複製進資料庫。
3. 既有環境變數 token 會繼續有效，管理台只會以「環境變數管理｜唯讀」顯示名稱及來源。
4. 原本沒有 Client API Key 的匿名部署會維持可用，只顯示非阻擋式安全建議。
5. 升級不會自動強制所有工具立刻改用新金鑰。

## 不停機建立替代金鑰

1. 在首頁「Proxy 專屬金鑰」選擇「建立替代金鑰」。
2. 立即保存只顯示一次的完整 token。
3. 使用畫面中的「測試連線」確認：
   - Proxy 金鑰驗證成功。
   - 至少一把 Ollama Cloud 上游金鑰可用。
   - 模型清單已就緒。
4. 逐一更新 OpenClaw、Kilo Code、VS Code 或其他工具。
5. 回到管理台確認新金鑰已有最近使用紀錄。
6. 保留舊金鑰一段時間，確認沒有遺漏的工具。
7. 再停用舊金鑰；確認服務正常後才刪除。

「立即更換」會讓舊 token 立刻失效，只適合已確認所有使用端能同步更新的進階情境。

## 從環境變數遷移

1. 建立新的管理台型 Proxy 專屬金鑰。
2. 測試新金鑰。
3. 更新所有外部工具。
4. 確認新金鑰已有成功使用紀錄。
5. 備份 `.env`。
6. 從 `CLIENT_API_KEYS` 移除已完成遷移的舊項目。
7. 重啟服務並再次測試。

管理台不會直接編輯環境變數金鑰，也不會顯示完整 token。

## 回退

需要暫時回退舊 image 時，請保留目前 `.env` 與 `data/`。1.6.0 不需要破壞性資料庫遷移，也不會自動搬移環境變數金鑰。回退後仍應重新測試既有工具連線與 `/health` 版本。
